# 商用架构复核：0.7 本地版本

这是0.7的历史审查，后续整改及待验收事项见[0.8交付说明](RELEASE-0.8.md)。

日期：2026-10-23（America/Los_Angeles）。结论：不批准当前版本直接对外商用。可以继续作为开发验证版本；真实客户与真实账务需要完成下述整改和验收。此次没有修改业务代码，也没有部署或同步 GitHub。

## 证据和限制

复核了 HTTP 授权、认证、仓储、运营、运单、财务、迁移及部署文件；重新运行现有测试，64/64 通过。另用隔离临时 SQLite 数据库验证了三个未覆盖场景，结束后删除临时数据，未修改实际业务库。复现通过服务层调用，未声称执行了浏览器视觉验收或公网渗透测试。

现有会话、密码哈希、CSRF、接口角色授权、客户范围查询、版本检查和事务是有效基础。JavaScript 语言本身不是“裸奔”的证据。已有这些控制也不能证明完整业务安全或生产可用。

## 上线阻断项

### 1. 高：运单换客户破坏关联数据归属

位置：`backend/modules/operations/service.mjs:26`。更新运单只验证目标客户启用及渠道资格，没有验证原归属、关联账单、地址或其他客户资料。

复现：客户 A 的运单 S 已关联客户 A 的账单 INV-A；调用运单操作把 S 分配给 B，接口对应服务接受更新。结果 S.customer_id=B，INV-A.customer_id=A，账单仍引用 S。客户隔离查询依据各记录 customer_id，无法修复关联不一致。

这是有权限员工操作造成的数据边界缺陷，不是已证实匿名或客户可以直接调用管理接口。历史运单还可能携带原客户填写的数据，因此不能把“员工有权限”当成允许任意转移的理由。

整改：已有归属默认禁止直接换客户；未归属数据分配需校验全部关联。确有业务转移需求时，建立单独审核流程，校验财务和资料关联、保存转移理由与前后快照，并在单一事务执行。增加跨客户负向测试。

### 2. 高：运单与财务状态之间缺少业务约束

位置：`backend/modules/shipments/service.mjs:47`、`backend/modules/operations/service.mjs:26`。

复现 A：创建 ready 运单及关联账单，并全额核销 10000 分；客户仍可取消运单，账单保持已核销 10000 分。代码没有要求退款、取消费、红字冲销或人工结算处理。

取消后保留历史账单本身不一定错误，缺陷是没有明确、可执行的取消结算政策与后续处理状态。

复现 B：delivered 运单仍可直接改实测箱重（测试从 1kg 改为 100kg），没有锁单、费用重算或差额审批。运单状态图存在，但不能保证跨模块业务闭环。

整改：先定义揽收、入仓、出库、签收、取消、退回的前置条件；明确何时锁定计费数据，以及更正、补收、退费、冲销规则。状态迁移必须统一执行业务约束并与账务操作事务一致。

### 3. 高：财务仍是内部账单登记，信用控制没有生效

位置：`backend/modules/operations/service.mjs:24`、`backend/modules/finance/service.mjs:35`、`:57`。

creditCents、settlement 是保存的客户属性；代码未将其作为接单、出库或放货的信用控制。财务 overview 返回空 accounts 和 null balance，核销明确标记 local_reconciliation；没有完整的账户流水、真实收款匹配、退款、冲销和资金账户体系。

客户改账单需审核、金额使用整数分、核销防超额是正确基础，但不能据此展示成已完成真实资金结算。账单明细允许手工录入，并没有从已锁定报价合同和实测费用自动形成不可重复计费的应收链路。

整改：建立报价版本和生效期、运单费用项、应收账单生命周期、收款与核销关联、退款/冲销及信用校验。哪些环节仍由人工或外部财务软件负责，必须明确责任边界和对账机制。

## 架构判断与实施顺序

模块化单体适合继续推进，不需要为显得专业立即拆微服务或重写成 Java。更换 UI 也不必然要求重写后端。真正要改变的是领域模型、跨模块不变量、权限职责及部署能力；应把业务规则从界面配置中进一步分离，并保留稳定 API 合约。

1. 先修复归属转移和关联一致性，再补全部跨客户与跨模块回归场景。
2. 与物流和财务负责人确认状态机、信用放行、计费、退费/冲销和审批规则，形成可执行验收案例。
3. 落实数据模型、价格快照、审计及职责分离；完成迁移验证与异常恢复。
4. 完成生产部署、备份恢复、容量和安全验证，再以受限客户与人工双重对账试运行。

放行需要上述证据，不能只以测试数量、页面相似度或能够启动作为标准。报告不是穷尽性安全证明，未覆盖的承运商、支付和现场仓储流程仍须按真实业务进一步验收。
