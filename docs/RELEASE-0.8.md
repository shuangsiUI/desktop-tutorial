# 0.8.1 架构整改与验收

本版修复 0.7 审查发现的核心数据和财务缺口，仍须经过目标环境与真实业务验收后才能批准商用。[0.7 审查](COMMERCIAL-READINESS-AUDIT.md)保留为历史记录；实际默认规则见[业务规则](COMMERCIAL-RULES.md)。

| 原审查项 | 本版实现 | 验证方式 |
| --- | --- | --- |
| 运单跨客户转移破坏关联 | 服务拒绝转移；关系表、外键、归属约束及迁移校验 | 服务与直接 SQL 负向测试 |
| 取消、签收实测与账单无约束 | 有效账单阻止取消；锁单、更正和作废审核 | 收款至取消闭环、错误更正整体回滚 |
| 信用额度无效 | 预付清账，账期无逾期且额度足够才放货 | 未计费、欠款、逾期、超额拦截 |
| 只有内部核销记录 | 收款关联、不可变借贷凭证、核销撤销、退款和冲销 | 重复收款、竞争退款、余额及应收对账 |
| 报价未绑定账单 | 实测锁价、费率和版本快照、重复开账拦截 | 调价不改变旧账单，更正使用原费率 |
| 查询全量扫描 | 运单/账单及管理主列表服务端分页、索引、SQL 汇总 | 分页隔离测试及本地容量检查 |
| 员工可直接维护费率 | 运营/财务申请，另一名管理员审核 | 自审拒绝、权限及过期版本测试 |
| 审计缺少目标客户和前后值 | 独立追加业务变更摘要；保留财务修订与审批记录 | 员工、目标客户、请求号检查 |
| 成功登录清除 IP 失败计数 | 仅清除该账号失败计数 | 跨账号喷洒限流回归 |
| 无 MFA | 生产员工强制 TOTP；独立密钥加密、防重放、重置撤销会话 | [RFC 6238](https://www.rfc-editor.org/rfc/rfc6238) 测试向量及登录回归 |
| 只有本机手工备份 | 流式加密备份、副本校验、独立恢复检查、监控退出码、systemd 模板 | 临时目录加密/副本/恢复/篡改拒绝测试 |

## 部署前仍需实际验收

1. 确认默认账期、信用、取消、费率模型与实际合同一致；用真实但脱敏案例让物流和财务负责人验收。
2. 安装 HTTPS 反向代理和服务，完成员工 MFA 绑定，并使用生产密钥管理。
3. 把备份副本目录挂载到真正独立的存储；模板目录不是“已完成异地备份”的证明。把 systemd 失败事件接入有人接收的告警渠道。
4. 在部署主机演练恢复，测量恢复点和恢复时间；本地隔离恢复检查不能代替整机故障演练。
5. 用实际数据量、导入大小和目标并发压测，做独立渗透测试。容量脚本只测隔离回环读请求，不构成生产 SLA。
6. 完成管理端新增操作与客户端分页的浏览器人工验收。本轮没有绕过已有浏览器访问权限限制，也没有声称完成视觉验收。

承运商实时路由/面单、银行或支付接口、财税系统、对象存储及文件病毒扫描仍未接入。当前仍为单实例 SQLite 模块化单体，未实现多实例高可用、跨地域容灾或分布式消息平台。需要这些能力时，应按业务规模专项实施，不能通过修改 UI 或监听地址获得。

## 可重复检查

```bash
npm test
npm run test:capacity
npm run db:check
npm run db:backup
npm run db:restore-check -- 备份文件
npm run ops:check
```

测试与容量脚本使用独立临时数据库；后四个运维命令使用配置的 DB_PATH 或备份目录。部署模板尚未安装到服务器，后台“运行与备份状态”将如实显示未验证项目。
